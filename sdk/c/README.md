# Rift C plugin SDK

Write Rift WebAssembly plugins in C (or C++) against the `rift:plugin@0.3.0`
contract in [`wit/rift-plugin.wit`](../../wit/rift-plugin.wit).

| File | What it is |
| --- | --- |
| `rift_plugin.h`, `rift_plugin.c`, `rift_plugin_component_type.o` | Bindings generated by `wit-bindgen c` 0.63.0. Do not edit; run `regenerate.sh`. |
| `rift_plugin_defaults.c` | Weak neutral implementations of every handler export. Define only the hooks you need. |
| `rift.h` | Header-only helpers: owned strings, text values, decisions, registration builders, wrappers for common host calls and background work, logging, rich text builders, a small JSON reader for configuration. |
| `build.sh` | Builds a plugin component from C sources. |
| `RiftPlugin.cmake` | `rift_add_plugin()` for CMake projects. |
| `regenerate.sh` | Regenerates the bindings from `../../wit` (`--check` fails on drift). |

See [`examples/plugins/hello-c`](../../examples/plugins/hello-c) for a complete
plugin.

## Toolchain

[wasi-sdk](https://github.com/WebAssembly/wasi-sdk/releases) 27 or newer
(CI uses 27). Its clang links a WebAssembly component directly for the
`wasm32-wasip2` target, so there is no separate componentization step:

```sh
$WASI_SDK_PATH/bin/clang --target=wasm32-wasip2 -mexec-model=reactor -O2 \
  -Wl,--strip-debug -I sdk/c -o plugin.wasm my_plugin.c \
  sdk/c/rift_plugin.c sdk/c/rift_plugin_defaults.c sdk/c/rift_plugin_component_type.o
```

Releases that ship target-prefixed driver links accept the same line as
`wasm32-wasip2-clang -mexec-model=reactor -o plugin.wasm my.c rift_plugin.c
rift_plugin_defaults.c rift_plugin_component_type.o`. `sdk/c/build.sh -o
plugin.wasm my_plugin.c` runs it for you (`WASI_SDK_PATH` defaults to
`/opt/wasi-sdk`); with CMake, configure with
`-DCMAKE_TOOLCHAIN_FILE=$WASI_SDK_PATH/share/cmake/wasi-sdk-p2.cmake` and call
`rift_add_plugin(my_plugin my_plugin.c)` after `include(sdk/c/RiftPlugin.cmake)`.

`-mexec-model=reactor` builds a library-style module without `main`. Strip
debug info (`-Wl,--strip-debug`) unless you need it: wasi-libc ships with
DWARF, which more than triples the size of a small plugin.

Check the result with `wasm-tools component wit plugin.wasm`: it must export
`rift:plugin/handler@0.3.x` and import the `rift:plugin/*` interfaces you use.

Toolchains that only produce core WebAssembly modules (wasi-sdk before 22, or
`--target=wasm32-wasip1`) need the manual path: build a `wasm32-wasip1`
reactor module, then
`wasm-tools component new module.wasm --adapt wasi_snapshot_preview1.reactor.wasm -o plugin.wasm`
with the reactor adapter from the matching Wasmtime release. The embedded
`rift_plugin_component_type.o` carries the WIT types either way.

## Writing a plugin

Implement the hooks you need with the exact generated signatures from
`rift_plugin.h` and return a registration from `init` that lists them, so the
host skips everything else (an empty hook list delivers every hook except
`chat` and `kick`):

```c
#include "rift.h"

bool exports_rift_plugin_handler_init(rift_string_t *config, rift_registration_t *ret, rift_string_t *err) {
  (void)err;
  rift_string_free(config);
  rift_registration_init(ret);
  rift_registration_add_command(ret, "hello", "hello.use", RIFT_PLUGIN_TYPES_SUGGEST_KIND_PLAYERS);
  rift_registration_add_hook(ret, RIFT_PLUGIN_TYPES_HOOK_COMMAND);
  return true;  // or set *err (an owned string) and return false
}

void exports_rift_plugin_handler_command(rift_context_t *ctx, rift_decision_t *ret) {
  rift_decision_message_fmt(ret, "Hello, " RIFT_STR_FMT "!", RIFT_STR_ARG(ctx->name));
  rift_context_free(ctx);
}
```

Host functions are the generated `rift_plugin_<interface>_<function>`
declarations, for example `rift_plugin_players_message`,
`rift_plugin_store_increment`, `rift_plugin_bus_publish` and
`rift_plugin_timers_every`. Functions returning `result<T, string>` return
`bool` and fill a `ret` and an `err` out-parameter; `option<T>` parameters are
pointers where `NULL` means `none`. `rift.h` wraps the common ones and logs
their errors: `rift_message`, `rift_action_bar`, `rift_title`, `rift_kick`,
`rift_broadcast`, `rift_show_dialog`, `rift_show_menu`, `rift_update_menu`,
`rift_close_menu`, `rift_player_lookup`, `rift_player_search`,
`rift_set_language` and `rift_add_group`.

Everything a player reads is a `rift_text_t`: `rift_text_plain("...")` or
`rift_text_json(json)`, both borrowed views for host calls and for the
`rift.h` helpers, which copy what they keep. `rift_text_dup` and
`rift_text_plain_fmt` make owned texts for values a handler returns.

### Chat and kick

`exports_rift_plugin_handler_chat(rift_chat_attempt_t *, rift_decision_t *)`
sees chat messages and backend commands before the backend does and may drop
them; `exports_rift_plugin_handler_kick(rift_context_t *, rift_decision_t *)`
runs when a backend kicks a player. Rift calls them only when the hook list
names them (`RIFT_PLUGIN_TYPES_HOOK_CHAT`, `RIFT_PLUGIN_TYPES_HOOK_KICK`). A
plugin that lists `chat` is asked about every message of every player; with
signed chat, the first deny costs that player their chat signing. See
[docs/plugins-c.md](../../docs/plugins-c.md#chat-and-kick).

### Menus

Inventory menus (chest, hopper, dispenser and anvil screens, Minecraft 1.12
and newer) are JSON text in the format of
[`docs/menus.md`](../../docs/menus.md): C has no builder. `rift_show_menu(&target,
json)` shows or redraws one, `rift_update_menu(&target, id, patch_json)`
changes a part and `rift_close_menu(&target, id)` closes it (`NULL` closes
whatever Rift menu is open). They log the host's error and return whether the
call was queued, like `rift_show_dialog`.

Everything a player does arrives at `exports_rift_plugin_handler_menu(
rift_menu_event_t *event)`, which needs no registration; the weak default
ignores events. The event is yours: free it with `rift_menu_event_free`.
`rift_menu_kind(event)`, `rift_menu_click(event)` and
`rift_menu_close_reason(event)` return enums (`RIFT_MENU_KIND_CLICK`,
`RIFT_CLICK_SHIFT_LEFT`, `RIFT_CLOSE_PLAYER`, ...) with an `_OTHER` case for a
value a newer Rift adds, so nothing compares strings.
`rift_menu_payload_string(event, &out)` and `rift_menu_state_string` read a
payload or state that is a JSON string (free `out` with `rift_string_free`)
and return a `rift_json_result_t`; the other fields are the generated options
(`event->action.is_some`, `event->slot.val`).

```c
void exports_rift_plugin_handler_menu(rift_menu_event_t *event) {
  rift_string_t server;
  if (rift_menu_kind(event) == RIFT_MENU_KIND_CLICK && event->action.is_some &&
      rift_string_eq(&event->action.val, "join") && rift_menu_payload_string(event, &server) == RIFT_JSON_OK) {
    rift_string_t err = {NULL, 0};
    bool moved;
    if (!rift_plugin_players_transfer(&event->ctx.uuid, &server, &moved, &err)) rift_string_free(&err);
    rift_string_free(&server);
  }
  rift_menu_event_free(event);
}
```

### Background work

A decision hook that needs a slow lookup calls `rift_background_defer(&ticket)`
and `rift_background_run(payload, len, &handle)` and returns. A background
worker, another instance of the component (`[background] workers = N` in
`plugin.toml`), runs `exports_rift_plugin_handler_work`; the main instance
then gets `exports_rift_plugin_handler_job_done` and answers with
`rift_background_resolve(ticket, &decision)`. See
[docs/plugins-c.md](../../docs/plugins-c.md#background-work).

### Memory ownership

These rules come from wit-bindgen's C generator and are the main source of
bugs in C plugins:

- **Handler arguments are yours.** Free them before returning
  (`rift_context_free(ctx)`, `rift_bus_message_free(msg)`, or the generated
  `rift_plugin_types_*_free`). The weak defaults do this for hooks you leave
  out.
- **Values you return are freed by the bindings** with `free()` once the host
  has copied them. Every non-empty string or list in a return value must come
  from `malloc`: use `rift_string_dup`, `rift_string_fmt`, `rift_text_dup`,
  `rift_decision_*`, `rift_suggestions_add` and `rift_registration_*`.
  Returning `rift_str("literal")` or a `rift_text_plain` view frees a pointer
  `malloc` never returned, which corrupts the heap or traps.
- **Arguments you pass to host functions are borrowed.** `rift_str("literal")`,
  `rift_text_plain("literal")` and fields of your handler arguments are fine;
  nothing is freed.
- **Results from host functions are yours.** Free `ret` and `err` strings and
  lists with `rift_string_free`, `rift_bytes_free`, `rift_string_list_free`,
  `rift_player_record_free` or the generated `rift_plugin_*_free` helpers.

A trap (including `abort()` on allocation failure) ends the call; the host
applies the manifest's `on_failure` and `restart` policies.

### Configuration

`init` and `reload` receive the plugin configuration as a JSON object
(`{}` without one). `rift_json_get_string(&config, "key", &out)` validates the
document and reads one top-level string member; anything richer deserves a
real JSON library (cJSON or jsmn compile unchanged with wasi-sdk).

### Rich text

`rift_mini` (markup, with `rift_mini_arg`/`rift_mini_arg_component`/
`rift_mini_arg_style`), `rift_legacy` (`&` codes), `rift_msg` (a message from
the plugin's `messages.toml`) and `rift_component`, `rift_translate`,
`rift_keybind`, `rift_sprite`, `rift_head` (fields, click and hover events,
children) return malloc'd JSON to wrap with `rift_text_json`.
`rift_text_escape` escapes text for splicing into markup:

```c
rift_mini_t m = rift_mini("<gold>Hi <player>!");
rift_mini_arg(&m, "player", "Steve");
char *json = rift_mini_finish(&m);
rift_message(&target, rift_text_json(json));
free(json);
```

A bare string is never markup. See
[C plugins](../../docs/plugins-c.md#rich-text-builders) and
[Text and markup](../../docs/text.md).

## Regenerating the bindings

```sh
cargo install wit-bindgen-cli --locked --version 0.63.0
sdk/c/regenerate.sh          # after changing wit/
sdk/c/regenerate.sh --check  # what CI runs
```

The bindings are generated for world `core`, the Rift imports plus the handler
export. A plugin built with wasi-sdk still satisfies world `plugin`: wasi-libc
carries its own WASI bindings, so the component imports exactly the WASI
interfaces libc uses (at the 0.2 patch version wasi-sdk targets; hosts link
WASI 0.2 semver-compatibly). Generating world `plugin` instead would duplicate
every WASI binding, and wit-bindgen (seen with 0.41 and 0.63) emits `*_free`
helpers that silently skip `option<string>`, `list<string>` and `list<u8>` fields
whose types are shared with WASI, which leaks memory on every hook.
