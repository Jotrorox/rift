# Rift C plugin SDK

Write Rift WebAssembly plugins in C (or C++) against the `rift:plugin@0.1.0`
contract in [`wit/rift-plugin.wit`](../../wit/rift-plugin.wit).

| File | What it is |
| --- | --- |
| `rift_plugin.h`, `rift_plugin.c`, `rift_plugin_component_type.o` | Bindings generated by `wit-bindgen c` 0.63.0. Do not edit; run `regenerate.sh`. |
| `rift_plugin_defaults.c` | Weak no-op implementations of every handler export. Define only the hooks you need. |
| `rift.h` | Header-only helpers: owned strings, actions, registration builders, logging, a small JSON reader for configuration. |
| `build.sh` | Builds a plugin component from C sources. |
| `RiftPlugin.cmake` | `rift_add_plugin()` for CMake projects. |
| `regenerate.sh` | Regenerates the bindings from `../../wit` (`--check` fails on drift). |

See [`examples/plugins/hello-c`](../../examples/plugins/hello-c) for a complete
plugin.

## Toolchain

[wasi-sdk](https://github.com/WebAssembly/wasi-sdk/releases) 27 or newer
(CI uses 27). Its clang links a WebAssembly component directly for the
`wasm32-wasip2` target, so there is no separate componentization step:

```sh
$WASI_SDK_PATH/bin/clang --target=wasm32-wasip2 -mexec-model=reactor -O2 \
  -Wl,--strip-debug -I sdk/c -o plugin.wasm my_plugin.c \
  sdk/c/rift_plugin.c sdk/c/rift_plugin_defaults.c sdk/c/rift_plugin_component_type.o
```

Releases that ship target-prefixed driver links accept the same line as
`wasm32-wasip2-clang -mexec-model=reactor -o plugin.wasm my.c rift_plugin.c
rift_plugin_defaults.c rift_plugin_component_type.o`. `sdk/c/build.sh -o
plugin.wasm my_plugin.c` runs it for you (`WASI_SDK_PATH` defaults to
`/opt/wasi-sdk`); with CMake, configure with
`-DCMAKE_TOOLCHAIN_FILE=$WASI_SDK_PATH/share/cmake/wasi-sdk-p2.cmake` and call
`rift_add_plugin(my_plugin my_plugin.c)` after `include(sdk/c/RiftPlugin.cmake)`.

`-mexec-model=reactor` builds a library-style module without `main`. Strip
debug info (`-Wl,--strip-debug`) unless you need it: wasi-libc ships with
DWARF, which more than triples the size of a small plugin.

Check the result with `wasm-tools component wit plugin.wasm`: it must export
`rift:plugin/handler@0.1.0` and import the `rift:plugin/*` interfaces you use.

Toolchains that only produce core WebAssembly modules (wasi-sdk before 22, or
`--target=wasm32-wasip1`) need the manual path: build a `wasm32-wasip1`
reactor module, then
`wasm-tools component new module.wasm --adapt wasi_snapshot_preview1.reactor.wasm -o plugin.wasm`
with the reactor adapter from the matching Wasmtime release. The embedded
`rift_plugin_component_type.o` carries the WIT types either way.

## Writing a plugin

Implement the hooks you need with the exact generated signatures from
`rift_plugin.h` and return a registration from `init` that lists them, so the
host skips everything else (an empty hook list delivers every hook):

```c
#include "rift.h"

bool exports_rift_plugin_handler_init(rift_string_t *config, rift_registration_t *ret, rift_string_t *err) {
  (void)err;
  rift_string_free(config);
  rift_registration_init(ret);
  rift_registration_add_command(ret, "hello", "hello.use", RIFT_PLUGIN_TYPES_SUGGEST_KIND_PLAYERS);
  rift_registration_add_hook(ret, RIFT_PLUGIN_TYPES_HOOK_COMMAND);
  return true;  // or set *err (an owned string) and return false
}

void exports_rift_plugin_handler_command(rift_context_t *ctx, rift_action_t *ret) {
  memset(ret, 0, sizeof *ret);
  ret->tag = RIFT_PLUGIN_TYPES_ACTION_MESSAGE;
  ret->val.message = rift_string_fmt("Hello, " RIFT_STR_FMT "!", RIFT_STR_ARG(ctx->name));
  rift_context_free(ctx);
}
```

Host functions are the generated `rift_plugin_<interface>_<function>`
declarations, for example `rift_plugin_players_message`,
`rift_plugin_store_increment`, `rift_plugin_bus_publish` and
`rift_plugin_timers_every`. Functions returning `result<T, string>` return
`bool` and fill a `ret` and an `err` out-parameter; `option<T>` parameters are
pointers where `NULL` means `none`.

### Memory ownership

These rules come from wit-bindgen's C generator and are the main source of
bugs in C plugins:

- **Handler arguments are yours.** Free them before returning
  (`rift_context_free(ctx)`, `rift_bus_message_free(msg)`, or the generated
  `rift_plugin_types_*_free`). The weak defaults do this for hooks you leave
  out.
- **Values you return are freed by the bindings** with `free()` once the host
  has copied them. Every non-empty string or list in a return value must come
  from `malloc`: use `rift_string_dup`, `rift_string_fmt`, `rift_action_*` and
  `rift_registration_*`. Returning `rift_str("literal")` frees a pointer
  `malloc` never returned, which corrupts the heap or traps.
- **Arguments you pass to host functions are borrowed.** `rift_str("literal")`
  and fields of your handler arguments are fine; nothing is freed.
- **Results from host functions are yours.** Free `ret` and `err` strings and
  lists with `rift_string_free`, `rift_bytes_free`, `rift_string_list_free` or
  the generated `rift_plugin_*_free` helpers.

A trap (including `abort()` on allocation failure) ends the call; the host
applies the manifest's `on_failure` and `restart` policies.

### Configuration

`init` and `reload` receive the plugin configuration as a JSON object
(`{}` without one). `rift_json_get_string(&config, "key", &out)` validates the
document and reads one top-level string member; anything richer deserves a
real JSON library (cJSON or jsmn compile unchanged with wasi-sdk).

## Regenerating the bindings

```sh
cargo install wit-bindgen-cli --locked --version 0.63.0
sdk/c/regenerate.sh          # after changing wit/
sdk/c/regenerate.sh --check  # what CI runs
```

The bindings are generated for world `core`, the Rift imports plus the handler
export. A plugin built with wasi-sdk still satisfies world `plugin`: wasi-libc
carries its own WASI bindings, so the component imports exactly the WASI
interfaces libc uses (at the 0.2 patch version wasi-sdk targets; hosts link
WASI 0.2 semver-compatibly). Generating world `plugin` instead would duplicate
every WASI binding, and wit-bindgen (seen with 0.41 and 0.63) emits `*_free`
helpers that silently skip `option<string>`, `list<string>` and `list<u8>` fields
whose types are shared with WASI, which leaks memory on every hook.
