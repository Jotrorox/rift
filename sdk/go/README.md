# Rift Go plugin SDK

Write Rift WebAssembly plugins in Go against the `rift:plugin@0.1.3` contract
in [`wit/rift-plugin.wit`](../../wit/rift-plugin.wit).

Module: `github.com/Jotrorox/rift/sdk/go`

| Package | What it is |
| --- | --- |
| `rift` | The SDK: plain Go types, a no-op default for every hook, `rift.OnInit`/`rift.OnLogin`/`rift.OnCommand`/... setters, host-call wrappers and configuration helpers. |
| `gen/...` | Bindings generated by `wit-bindgen-go` v0.7.0 for world `plugin`. Do not edit; run `regenerate.sh`. Use them directly only for something `rift` does not wrap. |

See [`examples/plugins/hello-go`](../../examples/plugins/hello-go) for a
complete plugin.

## Toolchain

Upstream Go cannot emit WebAssembly components yet
([golang/go#65333](https://github.com/golang/go/issues/65333)), so
[TinyGo](https://tinygo.org) is the supported compiler. TinyGo runs
`wasm-tools component embed`/`new` itself, so it needs
[`wasm-tools`](https://github.com/bytecodealliance/wasm-tools) on `PATH`, plus
`wasm-opt` from [Binaryen](https://github.com/WebAssembly/binaryen) (bundled
in TinyGo's Linux release; `brew install binaryen` on macOS).

**Use TinyGo 0.42.0** (CI does). Any release from 0.34 accepts the build line
below, but TinyGo 0.43.0 and 0.44.0 allocate the memory the host writes
arguments and results into (`cabi_realloc`) as manually managed memory that
the garbage collector never reclaims, and the generated bindings never free
it. Every hook call and every host call that passes strings or lists then
leaks: about 3 KB per round of five hooks in the hello-go conformance run,
against a flat 2 MB heap with 0.42.0.

```sh
tinygo build -target=wasip2 --wit-package path/to/rift/wit --wit-world plugin -no-debug -o plugin.wasm .
```

`--wit-package` also accepts a packaged WIT (`wasm-tools component wit
--wasm -o rift-plugin.wasm wit`). Check the result with
`wasm-tools component wit plugin.wasm`: it must export
`rift:plugin/handler@0.1.x` and import the `rift:plugin/*` interfaces you use.

Add this module to your plugin's `go.mod` (inside this repository use a
`replace` directive, as hello-go does):

```sh
go get github.com/Jotrorox/rift/sdk/go
```

## Writing a plugin

Register handlers in an `init` function. The host calls exports right after
instantiation and never runs `main`, which must exist but stays empty.

```go
package main

import "github.com/Jotrorox/rift/sdk/go/rift"

func init() {
	rift.OnInit(func(configJSON string) (rift.Registration, error) {
		rift.Every(1000) // timers and subscriptions are created in init
		return rift.Registration{
			Commands: []rift.CommandSpec{{Name: "hello", Permission: "hello.use", Suggest: rift.SuggestPlayers()}},
			Hooks:    []rift.Hook{rift.HookCommand, rift.HookTimer},
		}, nil
	})
	rift.OnCommand(func(ctx rift.Context) rift.Action {
		return rift.Message("Hello, " + ctx.Name + "!")
	})
	rift.OnTimer(func(handle uint64) { rift.Log(rift.LevelDebug, "tick") })
}

func main() {}
```

The host delivers only the hooks in `Registration.Hooks` (an empty list
delivers every hook). Leave `Hooks` nil and the SDK fills in exactly the hooks
you set a handler for; set it explicitly to send a fixed list, as hello-go
does. Hooks without a handler use the
defaults: `init` returns an empty registration, decision hooks `Continue()`,
`route` keeps the configured policy, `suggest` returns nothing, `status` and
`http` return no override, notification hooks do nothing.

Host calls are plain functions: `rift.SendMessage`, `rift.Kick`,
`rift.StoreIncrement`, `rift.Publish`, `rift.Reply`, `rift.Subscribe`,
`rift.Every`, `rift.Log`, `rift.HasPermission`, `rift.Control`, ... Calls
whose WIT result is `result<T, string>` return `(T, error)` with a
`rift.HostError`. Optional strings in parameters are `""` for none where the
empty string has no other meaning, and `*string` otherwise.

A panic traps the instance; the host applies the manifest's `on_failure` and
`restart` policies. The guest is single-threaded and the host never calls one
instance concurrently, so handlers need no locking.

### Configuration

`init` and `reload` receive the configuration as a JSON object (`{}` without
one).

- `rift.ConfigString(configJSON, "key")` validates the document and reads one
  top-level string with a built-in parser.
- `rift.DecodeConfig(configJSON, &cfg)` decodes into a struct with
  `encoding/json`. Convenient, but `encoding/json` adds roughly 850 KB to a
  TinyGo build (hello-go is 135 KB with `ConfigString`, about 1 MB with
  `DecodeConfig`).

### Rich text

`rift.Mini` (markup, with `Arg`/`ArgComponent`), `rift.Legacy` (`&` codes)
and `rift.Component` (fields, click and hover events, children) write the JSON
the `JSON` functions take, escaped and without `encoding/json`:

```go
msg := rift.Mini("<gold>Hi <player>!").Arg("player", ctx.Name)
rift.SendMessageJSON(ctx.UUID, msg.JSON())
```

`rift.SendTitleJSON` shows a title, and `rift.OnRichSuggest`/`rift.OnRichStatus`
answer with rich tooltips and server-list text (rift:plugin 0.1.3). A bare
string is never markup. See [Go plugins](../../docs/plugins-go.md#rich-text-builders)
and [Text and markup](../../docs/text.md).

### Size

`-no-debug` strips DWARF. If a plugin starts no goroutines,
`-scheduler=none` removes the asyncify scheduler and shrinks the output
further; with it, `go` statements fail to compile.

## Regenerating the bindings

```sh
sdk/go/regenerate.sh          # after changing wit/
sdk/go/regenerate.sh --check  # what CI runs
```

The script runs `go.bytecodealliance.org/cmd/wit-bindgen-go@v0.7.0` through
the Go module proxy; the generated code depends on
`go.bytecodealliance.org/cm` v0.3.0. Bytecode Alliance's newer Go generator
(`wit-bindgen go`, shipped in wit-bindgen-cli 0.63) targets upstream Go through
componentize-go and is not used here.
